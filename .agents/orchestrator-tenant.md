## Purpose & Scope
The Orchestrator Tenant agent manages the complete lifecycle of tenants on the USORA platform — from onboarding and provisioning to configuration, billing integration, and offboarding. It ensures that every tenant gets an isolated, secure, and compliant environment with zero manual infrastructure intervention.

## Tenant Isolation Strategy
- **Schema isolation**: `CREATE SCHEMA tenant_{tid}` per tenant in shared PostgreSQL cluster
- **Namespace isolation**: Dedicated K8s namespace `tenant-{tid}` per tenant
- **Resource quotas**: Per-tenant CPU/memory/storage limits enforced via K8s ResourceQuota
- **Network isolation**: Istio authorization policies per namespace; no cross-namespace traffic
- **Config isolation**: Tenant configs in Redis with `tenant:{tid}:config:*` prefix
- **Event isolation**: Kafka consumer groups per tenant; ACLs on topic prefixes
- **Billing isolation**: Per-tenant Stripe customer ID; usage metering per tenant
- **Audit isolation**: All tenant operations logged to tenant-specific audit stream

## Security Boundaries
- Tenant onboarding requires platform admin approval + compliance review
- Tenant offboarding triggers automated GDPR purge: schema drop, S3 prefix deletion, Kafka topic cleanup, Redis key purge
- Suspended tenants: all ingress blocked at gateway, compute scaled to zero, data retained but inaccessible
- Configuration changes require `tenant:admin` role; sensitive configs encrypted at rest
- No cross-tenant data access possible at any layer (enforced by schema + network + IAM)
- Tenant provisioning secrets (DB passwords, API keys) generated by Vault; never logged

## Failure Modes & Recovery
| Failure | Detection | Recovery |
|---------|-----------|----------|
| Schema creation failure | PostgreSQL error | Retry with exponential backoff, alert platform ops |
| K8s namespace creation failure | API server error | Retry, verify RBAC, alert |
| Vault secret generation failure | Vault API error | Retry, fallback to cached secret template, alert |
| Kafka topic creation failure | Admin client error | Retry, verify ACLs, alert |
| Offboarding incomplete | Purge job timeout | Escalate to manual review, GDPR incident log |
| Billing webhook failure | Stripe signature mismatch | Queue for retry, alert finance ops |

## Configuration
```yaml
tenant:
  provisioning:
    auto_approve: false  # Require manual approval for new tenants
    schema_prefix: "tenant_"
    namespace_prefix: "tenant-"
    default_resource_quota:
      cpu: "10"
      memory: "20Gi"
      storage: "100Gi"
      pods: "50"
  offboarding:
    grace_period_days: 30
    purge_immediately: false  # Soft delete first, hard purge after grace period
    gdpr_compliance: true
    audit_retention_years: 7
  billing:
    provider: "stripe"
    webhook_secret: "${VAULT:stripe_webhook_secret}"
    usage_reporting_interval: "1h"
  suspension:
    auto_suspend_on_payment_failure: true
    auto_suspend_after_days: 7
    data_retention_during_suspension: "90d"
```
